Funcions de grup i agrupaments

Criteri 3.5 — COUNT, SUM, AVG, MAX, MIN · GROUP BY · HAVING

Les funcions de grup operen sobre conjunts de files i retornen un sol valor per grup. Amb GROUP BY es calcula un agregat per a cada grup de valors. HAVING filtra els grups resultants (mai s'usen funcions de grup al WHERE).

FuncióDescripcióNota sobre NULLs
COUNT(*)Nombre total de filesInclou NULLs
COUNT(col)Files amb valor no NULL a colIgnora NULLs
COUNT(DISTINCT col)Nombre de valors únics no NULLIgnora NULLs i duplicats
SUM(col)Suma dels valorsIgnora NULLs
AVG(col)Mitjana (divideix pel nombre de valors no NULL)Ignora NULLs
MAX(col) / MIN(col)Màxim / mínimFunciona amb dates i text
Regles fonamentals
1. Tota columna al SELECT que no estigui dins d'una funció de grup ha d'aparèixer al GROUP BY.
2. WHERE no pot contenir funcions de grup → usar HAVING.
3. Ordre d'execució: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
Exemple 1 · Funcions de grup sense GROUP BY
Explicació
Quan s'usen funcions de grup sense GROUP BY, s'apliquen a tota la taula i retornen una sola fila. COUNT(*) compta totes les files incloent NULLs. COUNT(col) ignora els NULLs. AVG també ignora els NULLs: el divisor és el nombre de valors no NULL, no el total de files.
Exemple 2 · GROUP BY i HAVING
Explicació
GROUP BY agrupa les files amb el mateix valor i les funcions de grup calculen un resultat per a cada grup. HAVING filtra els grups (com WHERE però per a grups). Ordre d'execució: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. Mai s'usa una funció de grup al WHERE.
Exemple 3 · Taula pivot amb DECODE dins SUM
Explicació
DECODE dins de SUM o COUNT permet crear taules de pivot (crosstab): per a cada fila, si el departament coincideix aporta el salari, si no aporta NULL (que SUM ignora). El resultat és una fila per càrrec amb una columna per departament.

2

Unions entre taules (JOINs)

Criteri 3.3 · 3.4 — INNER JOIN, OUTER JOIN, self-join, NATURAL JOIN

Quan la informació es troba repartida en diverses taules, cal unir-les. Oracle SQL segueix l'estàndard SQL:1999 amb les clàusules JOIN ... ON, JOIN ... USING i NATURAL JOIN.

INNER JOIN

Retorna només les files que tenen coincidència en les dues taules. Les files sense parella queden fora.

LEFT OUTER JOIN

Retorna totes les files de la taula esquerra, amb NULL on no hi ha coincidència a la dreta.

RIGHT OUTER JOIN

Retorna totes les files de la taula dreta, amb NULL on no hi ha coincidència a l'esquerra.

FULL OUTER JOIN

Retorna totes les files de les dues taules, amb NULL on no hi ha coincidència en cap costat.

Exemple 4 · NATURAL JOIN, JOIN USING, JOIN ON
Explicació
NATURAL JOIN uneix automàticament per totes les columnes de nom igual (còmode però perillós si hi ha columnes homònimes no relacionades). JOIN ... USING(col) especifica quina columna comuna usar; la columna USING no s'ha de qualificar amb àlies de taula. JOIN ... ON és la forma més explícita i flexible: permet qualsevol condició d'unió i és la recomanada en producció.
Exemple 3 · JOIN de 3 taules, self-join i LEFT OUTER JOIN
Explicació
El self-join uneix la taula amb ella mateixa amb àlies diferents. Imprescindible per a jerarquies (empleat–cap). LEFT OUTER JOIN inclou el president (sense cap): la seva fila tindria NULL a la columna del gestor.
JOIN per rang de valors (no equijoin)
Quan la condició d'unió no és una igualtat sinó un rang, s'usa BETWEEN al ON. Exemple clàssic: taula JOB_GRADES amb columnes LOWEST_SAL i HIGHEST_SAL.
ON e.salary BETWEEN j.lowest_sal AND j.highest_sal

Subconsultes

Criteri 3.6 — Consultes dins de consultes

Una subconsulta és una sentència SELECT dins d'una altra sentència SQL. S'executa primer i el seu resultat s'usa com a valor o conjunt de valors per a la consulta externa.

TipusRetornaOperadors compatibles
D'una sola filaExactament un valor= != < > <= >=
De múltiples filesDiverses filesIN NOT IN ANY ALL EXISTS
Al FROM (inline view)Una taula virtualEs tracta com una taula normal
CorrelacionadaDepèn de la fila exteriorEXISTS NOT EXISTS
ANY vs ALL
> ANY(subconsulta) = major que com a mínim un valor = major que el mínim.
> ALL(subconsulta) = major que tots els valors = major que el màxim.
= ANY és equivalent a IN. != ALL és equivalent a NOT IN.
Exemple 7 · Subconsulta d'una sola fila
Explicació
La subconsulta s'executa primer i retorna un sol valor que usa la consulta externa. Si la subconsulta retornés més d'una fila amb l'operador =, Oracle donaria error. En aquest cas cal usar IN o ANY.
Exemple 8 · Subconsultes de múltiples files: IN i ANY/ALL
Explicació
IN comprova si el valor pertany al conjunt retornat per la subconsulta. > ANY significa "major que almenys un valor" (equivalent al mínim del conjunt). > ALL significa "major que tots els valors" (equivalent al màxim). = ANY és equivalent a IN.

Operadors de conjunt

Criteri 3.7 — UNION, UNION ALL, INTERSECT, MINUS

Els operadors de conjunt combinen els resultats de dues o més sentències SELECT. Les dues consultes han de tenir el mateix nombre de columnes amb tipus de dades compatibles.

OperadorDescripcióElimina duplicats?
UNIONTotes les files d'ambdues consultesSí
UNION ALLTotes les files d'ambdues consultesNo (més ràpid)
INTERSECTNomés les files presents a les dues consultesSí
MINUSFiles de la primera que no estan a la segonaSí
TO_CHAR(NULL) per alinear columnes
Quan les dues consultes d'un UNION han de tenir el mateix nombre de columnes però una no té dades per a una columna concreta, s'usa TO_CHAR(NULL) (o TO_NUMBER(NULL)) per afegir un valor NULL amb el tipus adequat.
Exemple: SELECT last_name, department_id, TO_CHAR(null) dept_name FROM employees
Exemple 9 · UNION, UNION ALL, MINUS i INTERSECT
Explicació
Les dues consultes han de tenir el mateix nombre de columnes i tipus compatibles. UNION elimina duplicats (més lent); UNION ALL els conserva (més ràpid). MINUS retorna les files de la primera consulta que no apareixen a la segona. INTERSECT retorna les files comunes. L'ORDER BY s'escriu al final de l'última consulta i fa referència al nom o posició de la primera.

5

Bones pràctiques i optimització

Criteri 3.8 — Escriure SQL que escala bé

Una consulta correcta i una consulta eficient no sempre és el mateix. Quan les taules creixen a milions de files, certes decisions d'escriptura poden marcar la diferència entre una resposta instantània i una espera de minuts.

El pla d'execució: com llegeix Oracle la consulta

Abans d'executar qualsevol sentència SQL, l'optimitzador d'Oracle (CBO, Cost-Based Optimizer) decideix el camí més eficient: quin ordre seguir per unir taules, si usar un índex o llegir tota la taula, etc. Es pot consultar amb EXPLAIN PLAN.

Exemple 10 · Consultar el pla d'execució
Explicació
EXPLAIN PLAN FOR no executa la consulta; només calcula i desa el pla. Després es visualitza amb DBMS_XPLAN.DISPLAY(). Els dos conceptes clau del pla: Full Table Scan (FTS) = llegeix tota la taula fila a fila (lent en taules grans); Index Range Scan = usa un índex per anar directament a les files que compleixen la condició (molt més ràpid).
Índexos: quan ajuden i quan no
SituacióOracle usa l'índex?
WHERE last_name = 'King'✓ Sí — comparació directa
WHERE salary BETWEEN 5000 AND 10000✓ Sí — rang sobre columna indexada
WHERE UPPER(last_name) = 'KING'✗ No — funció sobre columna indexada
WHERE salary + 1000 > 8000✗ No — operació aritmètica sobre columna
WHERE TO_CHAR(hire_date,'YYYY') = '2005'✗ No — funció sobre columna indexada
WHERE hire_date >= TO_DATE('01/01/2005','DD/MM/YYYY')✓ Sí — la funció és sobre el literal, no sobre la columna
Sargability
Una condició és sargable (Search ARGument ABLE) quan permet usar un índex. La regla principal: no apliquis funcions a la columna indexada al WHERE; aplica-les al literal de comparació. Exemples:
✗ WHERE TRUNC(hire_date) = TRUNC(SYSDATE) → no sargable
✓ WHERE hire_date >= TRUNC(SYSDATE) AND hire_date < TRUNC(SYSDATE)+1 → sargable
EXISTS vs IN: quin és més eficient?
Exemple 11 · EXISTS vs IN per a subconsultes correlacionades
Explicació
EXISTS s'atura tan bon punt troba la primera coincidència (short-circuit), mentre que IN carrega tot el conjunt de la subconsulta a memòria i després compara. En taules grans, EXISTS és generalment més eficient quan la subconsulta pot retornar moltes files. NOT EXISTS és preferible a NOT IN perquè NOT IN retorna cap fila si la subconsulta conté algun NULL.
Bones pràctiques generals
✓ Recomanat
Evitar SELECT * en producció — triar només les columnes necessàries.
Filtrar amb WHERE el més aviat possible per reduir el nombre de files processades.
Usar EXISTS en lloc de IN amb subconsultes grans.
Fer que les condicions del WHERE siguin sargables: no aplicar funcions sobre columnes indexades.
Usar UNION ALL en lloc de UNION quan se sap que no hi ha duplicats (evita el pas de deduplicació).
Limitar el nombre de files amb FETCH FIRST n ROWS ONLY quan no es necessite tot el resultat.
✗ Errors habituals
Usar = NULL en lloc de IS NULL (no retorna mai files).
Posar funcions de grup al WHERE en lloc de HAVING.
Usar NOT IN (subconsulta) quan la subconsulta pot retornar NULLs (retorna 0 files).
Aplicar funcions sobre columnes indexades al WHERE (invalida l'ús de l'índex).
Usar UNION quan UNION ALL seria suficient i correcte.
Exemple 12 · Paginació amb FETCH FIRST (Oracle 12c+)
Explicació
FETCH FIRST n ROWS ONLY és la sintaxi estàndard SQL:2008 per limitar el nombre de files del resultat (equivalent a ROWNUM <= n però més llegible i correcte amb ORDER BY). OFFSET n ROWS permet saltar les primeres n files, útil per a paginació.
